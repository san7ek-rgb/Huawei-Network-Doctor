# Huawei Network Doctor

Приложение для Windows 10/11 x64 на Python 3.12 и PySide6. Сравнивает одно подключение через домашний Wi-Fi с другим через мобильную точку доступа. Диагностика работает в режиме чтения и не требует запуска от администратора. Права администратора нужны только для подтверждённого пробного изменения MTU и его отката.

## Запуск на Windows

Установите Python 3.12 x64. В PowerShell из корня проекта выполните:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe launcher.py
```

Для знакомства используйте кнопку «Загрузить демонстрацию А и Б» или передайте `--demo`.

## Как проверить проблему VPN

1. На домашнем Wi-Fi запустите обычную проверку. Посмотрите основной маршрут, активные туннельные адаптеры, ответы шлюза, DNS и внешнего узла. Вкладка Huawei покажет результат запроса к локальному шлюзу.
2. Во вкладке VPN повторите неудачное подключение в самом клиенте. Выберите журнал последней попытки. При необходимости укажите разрешённый для проверки адрес, порт и фактический транспорт профиля. Запустите тест А.
3. Переключитесь на мобильную точку доступа. Убедитесь, что Windows использует её, повторите попытку с тем же клиентом и профилем, выберите актуальный журнал и запустите тест Б.
4. Откройте «Найденные проблемы». Отличия в DNS, TCP и результате рукопожатия проверяют разные этапы соединения. Успех TCP подтверждает только TCP-соединение. При UDP приложение использует признаки из журнала клиента. Сопоставьте время записи и попытки вручную. Повторите процедуру отдельно для второго клиента.
5. Просмотрите и экспортируйте отчёт. По умолчанию из экспорта исключаются IP-адреса, имена серверов, SSID, MAC-адреса, сырые маршруты и журналы. Предпросмотр совпадает с экспортом. Локальная история содержит подробный сетевой снимок и хранится в `%LOCALAPPDATA%\HuaweiNetworkDoctor\history`.

Обычная диагностика выполняет DNS-запрос для `example.com`, ICMP к шлюзу и `1.1.1.1` и HTTP(S) к обнаруженному шлюзу. TCP к VPN-серверу запускается после отдельного согласия. В отчёте различие между сетями представлено как наблюдение и гипотеза о причине.

## Huawei и Wi-Fi

Панель проверяется по обнаруженному IPv4-шлюзу. Признаки Huawei и модель в HTML являются подсказкой. При недоверенном сертификате приложение показывает статус проверки и предлагает открыть адрес в браузере. Для прошивки, WAN, ширины канала, firewall и VPN passthrough используйте инструкцию на вкладке Huawei и документацию своей модели. Приложение не принимает и не хранит пароль роутера.

Автоматическое чтение настроек через API пока не поддерживается ни для одной модели, включая HG8245H, B535-232, серии EG, AX и WS. HG8245H и B535-232 покрыты симуляцией распознавания HTML. Универсальное обнаружение панели применяется к другим моделям, если панель отвечает по HTTP(S) на стандартном порту шлюза. Некоторые версии Windows ограничивают данные Wi-Fi без разрешения на определение местоположения. Режим только IPv6 и собственный адрес или порт панели требуют ручной проверки.

## Скорость и откат

Во вкладке скорости можно снять три последовательных показания Wi-Fi и провести замер Cloudflare по HTTPS с отдельным согласием (10 МБ на скачивание и 2 МБ на отдачу). Это короткий замер прикладной скорости. Для сравнения до и после изменения выберите соответствующий этап и используйте одно подключение. Задержка, джиттер и потери взяты из ICMP-проб; ICMP может фильтроваться отдельно. Радиоскорости и доступные каналы показаны по выводу Windows, который зависит от драйвера и языка системы.

MTU-тест оценивает отдельный путь по IPv4, и отсутствие ICMP-ответа не доказывает причину проблемы. Интерфейс допускает пробное изменение после живого замера с меньшим проходящим размером, сверки индекса и отдельного подтверждения. Для исходного и пробного значения сохраняется локальная резервная копия. «Восстановить исходный MTU» проверяет идентификатор адаптера и текущее значение. Изменения DNS, маршрутов, драйверов, VPN и роутера выполняются вручную по рекомендациям.

## Тесты и сборка EXE

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\build.ps1 -Python .\.venv\Scripts\python.exe
```

Сборка на Windows создаёт `dist\HuaweiNetworkDoctor.exe`. Скрипт проверяет зависимости, тесты, запуск оконного приложения и запуск упакованного EXE. На GitHub workflow **Windows build** собирает тот же файл и публикует его как артефакт после успешной проверки. Сборка не подписывается.

В Linux можно проверить интерфейс на симуляции командой `QT_QPA_PLATFORM=offscreen python launcher.py --smoke-test`. Проверку Windows, вашей сети, роутера, клиентов и EXE выполняйте на Windows. [Пример обезличенного отчёта](docs/example-report.json) содержит симулированные данные.
